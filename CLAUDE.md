# Potluck

A block sandbox where every creature, block and mini game is a Luau creation players can read, tweak, remix and share by code, in Rust on Bevy 0.20 with Luau through mlua. The concept is idea 26 in [game-ideas](https://github.com/LinuxGroove/game-ideas/blob/main/ideas/26-potluck.md). Like Cinderkirk it is **not Godot** and doesn't use the shared add-on; it talks to the shared [game server](https://github.com/LinuxGroove/game-server) over its REST API (signing in, the codes made before the market, the launch ping), and its own market (`crates/share-service`) keeps and lists creations.

## Commands

```sh
cargo build --bins                         # the game (potluck), the server (potluck-server) and the market (potluck-share)
cargo test                                 # world, creations, sandbox, a friend joining, wss and https, the market's checks
deploy/market/test.sh                      # the market end to end against Forgejo (its own release, kept in build/forgejo): sharing, reviews, a remix of a remix, a suggestion merged from the game
FORGEJO_TOKEN=$(cat build/forgejo/token) cargo run -p potluck-share -- --config deploy/market/share.toml   # the market by hand, on test.sh's Forgejo; potluck-share check FOLDER runs its checks
cargo run --bin potluck -- --play          # straight into the world (--windowed for a window this once; --bridge turns the dev bridge on)
cargo run --bin potluck --features raytracing -- --play --lighting=ultra   # Ultra ray traced (Bevy's Solari), on cards with ray queries
cargo run --bin potluck-server -- --port=47126 [--config=server.toml] [--tls-port=47443 --cert=fullchain.pem --key=privkey.pem]
cargo run --bin potluck-server -- --test=balloon|path/to/folder|all   # creations' own tests (test.luau), each case in a fresh world; ends with 1 if any failed
cargo run --bin potluck-server -- --typecheck=balloon|path/to/folder|all   # Luau's type checker over creations, only what it's sure of; ends with 1 if it found anything
cargo run --bin potluck-bots -- --address=ws://127.0.0.1:47126 --bots=50 --minutes=60 --build --report=/tmp/soak.jsonl   # bot players for soak tests
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1280x720x24" target/debug/potluck --demo=/tmp/demo --size=1280x720   # scripted play-through, recorded (about 1.5 s a frame on 4 CPUs)
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1600x900x24" target/debug/potluck --shot=/tmp/a.png --after=8 [--at=x,y,z,yaw,pitch] [--time=0.8] [--at=creature:N|name] [--person[=hue]] [--screen=play|inside|tweak|pause|title|map|chat|keyboard|settings[:page]|creations[:shelf]|blocks[:page]|market|question|share|friends|worlds|backpack] [--lines] [--lighting=low|medium|high|ultra] [--no-vsync | --present=immediate|mailbox|fifo|relaxed] [--latency=N] [--onscreen] [--timings]   # logs the frame rate too; --timings adds where frames go (lengths, main and render world, waiting for the screen) and each render pass's CPU and GPU time
tools/tiers.sh [out=/tmp/potluck-tiers] [size=2560x1440] [binary]   # every lighting tier from four places, with frame rates and memory (on a real graphics card)
POTLUCK_MEMORY=30 cargo run --bin potluck -- --play   # a line of RAM and graphics memory every 30 s (--memory=30 too); every run logs the full report when it quits
python3 tools/memory_watch.py [~/potluck-memory] [2]   # writes down every Potluck process's RAM, graphics memory and CPU on this machine, from outside
tools/snap-project.sh potluck-server && (cd build/potluck-server && snapcraft pack)   # the server snap (potluck-market for the market's)
CYCLES_DEVICE=OPTIX python tools/blocks.py -- assets/blocks 256 [only=grass_top,dirt]   # bake block textures (bpy wheel in a venv; drop CYCLES_DEVICE without a GPU)
POTLUCK_DUMP_TEX=/tmp/tex cargo test -p potluck dump_textures && python3 tools/title.py /tmp/tex assets/title/potluck.png   # the title picture: Bungee in the game's own dirt and grass (Pillow, numpy)
```

Run the tests before every commit. Set `POTLUCK_HOME` to a scratch folder for runs that shouldn't touch your own world and settings. Without a GPU, launches take a minute or more under lavapipe (most of it Bevy's pipelines compiling); `libxkbcommon-x11-0` and `mesa-vulkan-drivers` must be installed. A local `.cargo/config.toml` with clang and mold speeds up linking; it isn't committed.

## How the game is built

- **One world, many views.** `sim()` holds the voxels, the library, the running creations and the herd. Alone or hosting, `game::host_step` runs creations and creatures; a client only mirrors what the host sends. The server is `sim()` with no window and no `Me`.
- **An endless world** (`world.rs`, `world/`): blocks live in 32 x 32 columns from y = -128 (bedrock, ragged a few blocks up; slate below about `SLATE_Y`) to 128, each eight 32-block sections kept as one block when they're all one (`column.rs`), found through a dense grid over what's loaded. The island (0 to 384 each way) is made whole from the seed, exactly as it always was above y = 0 (a test checks its print), and is always loaded; past it `wild.rs` makes each column on its own from pure functions of (seed, x, z): open sea round the island, then meadows and woods like the island's, and further out pine woods, snowfields, deserts, dry grassland, marshes and mountains, with rivers (`climate`, `height`, `biome`). Trees reach over a column's edge, so a column is laid out with a 12-block margin and every tree whose trunk is in it is grown too, each from its own seed in the same order, and only the column's own blocks kept (a test checks columns made alone match those made together). `stream::stream` makes the columns round this game's own player a column past the view (`mesh::View`, by lighting tier), and on a host or server round everyone who joined (`AROUND_FRIENDS`), four at a time on `AsyncComputeTaskPool`, nearest first, and lets go of those nobody's near (kept whole, run-length encoded, if anyone changed them). Land that isn't made yet is solid to players and creatures (`player::blocked`) and creatures there wait; `world.top` there says where the seed puts the ground, and `set` makes it. Saves (`POTLUCKW3`) and a joining friend's welcome carry only the columns anyone changed, whole (`Voxels::encode`), and the seed makes the rest, so a game making a column it hasn't got applies the host's changes to it as it comes (`pending`). `world::below` is where caves and ores go (the survival work's `underground`), `keep_out` the places they never cut, and `GEN` the generator's version: bump it and `net::PROTOCOL` when what the seed makes changes. `mesh::show` draws the columns in view whose neighbours are all here (the island whole when it's near), chunks solid right through or all air aren't meshed, and `render::far` draws the land past them (below).
- **Creations are the game.** Base content is creations too (`creations/mossback`). A creation's VM never touches Bevy: calls go through a scoped API that reads and changes the world and herd, and anything a creation can do must be safe for a stranger's code: no files, no network, no `loadstring`, a memory cap and an interrupt deadline. `AGENTS.md` and `types/potluck.d.luau` describe the API; keep them in step with `script.rs`, and version API modules on their own (`@potluck/world@0.12`, `MODULES` in `script.rs` and in the market's `checks.rs`). docs/api.md is the promise: a minor version only adds, every major stays, the limits only loosen; update its tables and change list with every module change.
- **Hot reload keeps state.** Restarting a VM carries each creature's fields over as JSON and restyles bodies; tests check it.
- **Networking** is WebSocket binary messages: tag 0 is a JSON `Msg`, tag 1 the world's bytes. The same port answers plain HTTP with the status page and `/status.json`. TLS comes from a certificate (`--cert`, `--key`) or a proxy in front (the snap's Caddy). Each player hears only about players and creatures within `NEAR` (144 blocks), as changes since what they last heard, with far ones (past 32) a quarter as often; names and kinds go once. Keep messages small: soak with `potluck-bots --pid=<server>` after changing what's sent (its `kb_per_second_by_kind` shows what each message costs; docs/hosting.md has the numbers to beat).
- **Servers** (`hosting.rs`, `server.rs`): `Rules::admit` decides who comes in. A pass is the market's Ed25519 signature over `{handle, name, aud, exp}`, checked with the key the server fetches at start; `aud` is the address the player typed, compared by `same_address`. Creations keep boards through `@potluck/game` (`Scripts::shared`), saved in `boards.json` and pushed to the market with the heartbeat; `game.send` uses the server's `[links]`. What creations keep with `@potluck/store` (`script::Store`, 64 KB each) is saved beside them in `store.json`.
- **The market** (`share.rs` in the game, `crates/share-service`): the game signs in to the game server with its device id and gives the market that session, which the market checks with the game server; no emails or passwords. An account is keyed by the first device's id; other devices join it with a link code or a one-time recovery code (`devices.rs`: `devices` maps a device to the account it plays as, so `game_account` resolves through it, and codes are kept as hashes). The market keeps one code per creation that loads its newest version anyone may load, signs each version's manifest (Ed25519; release builds carry the key as `POTLUCK_MARKET_KEY`, others keep the first one seen) and serves files by SHA-256, which the game checks and caches. Codes made before the market still load from the game server, and sharing by code falls back to it when the market is down. A remix's `potluck.toml` carries `[from]` (code and version, or a base creation's id), and `market.json` in the data folder keeps each of the player's creations' code and version there.
- **Sharing a world from home** (`p2p.rs`, Share this world on the pause menu, Join a friend's world): the game asks the market for a world code first (`share::share_world`: 6 characters, kept per world as `slot` until New code, live only while the game beats once a minute, `game::share_heartbeat`), then listens on an iroh endpoint with a fresh key (`Net::share_from_home`); friends ask the market for the way in (`join_world`: the host's key, addresses and a pass with `aud = p2p:<host key>` and `peer = <the friend's key>`) and dial it (`Net::join_p2p`). The market decides who may come (Friends, or Anyone with the code; younger players only into a friend's world set to Friends, and a younger host's world is always Friends), and the host's game checks the pass and its key (`Rules::admit_peer`). The relay (iroh-relay, a service in the market's snap on HTTPS port 8443 with Caddy's certificate, until it needs a machine of its own) asks the market (`/api/relay/allow`) before carrying a key, and only keys it gave out pass. `Wire::Link` says which way each connection goes, shown to both players. Always connect through LinuxGroove (`Settings::through_relay`, on for younger players) drops IP transports, so nobody learns the player's address. Messages are unchanged, so `PROTOCOL` stays; LAN hosting and sharing from home can run at once.
- **Friends** (`friends.rs` in the market, `Screen::Friends` in the game): 8-character friend codes (New friend code replaces it), requests that become friendships when answered (or at once when both asked), removing and blocking (a block looks like a wrong code to the blocked). A younger player's new friends need the parent PIN (`Screen::ParentOk`, then `Act::Approved`) unless a parent turned that off, and parents can turn sharing and joining worlds off.
- **Ages** (`Settings::young`, the market's `accounts.young` from the game's `X-Potluck-Young` header, `versions.all_ages`, a server's `all_ages`): asked once before anything goes online (`game::goes_online`); younger players share by code only, send no suggestions, have no about line, and listed servers that aren't all-ages refuse their passes. Parent settings sit behind a hashed PIN. New market columns go in `db::ADDED`, so older databases gain them on start.
- **Creations' buttons** (`@potluck/input`): actions are `[actions.id]` in `potluck.toml` (name, pad, keys), so the game and the market know them before anything runs. `input::claim` makes the live creation's buttons (riding its creature, or `input.focus`) do its actions instead of the game's; `game::interact` sends `Action::Press` to the host on each change, and the host takes a press only while it's live for that player. `input.focus` reaches players as `Msg::Focus`. Players' own buttons are `Settings::bindings`. Keep `PAD_BUTTONS` and the keys in `input.rs` and the market's `checks.rs` in step.
- **Creations' screens** (`@potluck/ui`): `ui.show` and `ui.ask` change `UiState` on the host; `Scripts::ui_changes` turns that into what each player should see, sent as `Msg::Piece` and `Msg::Panel` (or straight into `Me` for the host's own player). A panel opens as `Screen::Panel` only from play, never over a menu, always says whose it is and always has Close; `Action::Answer` goes back to the host, which checks it against that player's panel. Every question gets one answer, nil included, on a later tick.
- **Underground** (`underground.rs`): `carve(seed, x, y, z, ground, b)` decides one block from the seed and where it is, with nothing from the world, so any column comes out the same anywhere and in any order: tunnels where two noises are near zero, caverns below 0, cave mouths only inland, ore veins (one of each ore per grid cell, kept inside it, each ore at its depths), crystal hollows, and old workings (an 80-block region's corridors, posts, beams and old chests; boards where a cave would leave a hole under them). It only changes stone, dirt and gravel (and grass or snow where a cave mouth comes out). Thread-local caches (each noise's levels for the column being made, and vein cells) save the hashing for a column's next blocks and change no answer. `world::below` runs it on every block of every column as it's made, the island's and the land past it, except where `world::keep_out` says (asked only when carving changes a block); bump `world::GEN` when what it carves changes.
- **What players carry** (`world.pockets`, `has`, `take`, `give`, `items.rs`): a `Thing` (u16) is a block (its block id, under 256) or an item (the game's own from `items::FIRST_ITEM`, 256, in `items::ITEMS`; never renumber). Pockets are `items::Slots`: 36 slots, the hotbar's nine then the backpack's 27, up to `items::stack` of a thing each (99 of a block, one tool); `give` tops up then fills empty slots hotbar first, `take` empties the backpack first, and a hotbar slot that runs out while building takes the backpack's next lot (`refill`). In survival a slot with a count of 0 is empty whatever thing it last held, so compare pockets by `filled()`. They live on each player's game: `player::report_pockets` sends `Action::Pockets` (the filled slots) when they change (the host's own player too); the host keeps a copy in `GameShared.pockets` and gives and takes on it as the player's game will, so creations' changes go back as `Msg::Pockets` with a count and land in the same slots, and a report from before they arrived is ignored (`Scripts::set_pockets`). The backpack (`Screen::Backpack`, the Blocks key in survival) shows `Focus.pockets`, a copy, and moves things with `Act::Slot` (`Slots::shift`: all or half, stacking or swapping) and `Act::Tidy`. Creative players have everything and nothing is counted. Health works the same way: `world.hurt` and `world.heal` (survival players only) go back as `Msg::Health` (or straight into `Me.health_due` for the host's own player), and `player::walk` applies them in survival. Creations see the time of day through `GameShared.day`, which `host_step` sets from `render::Clock`.
- **Block events** (`block_placed`, `block_broken`, `block_used`) are only what players do: the host's own player's builds go through `Me.built` into `Scripts::player_block` in `host_step`, a friend's through `host_net`'s `Msg::Blocks`, and Interact on a block (when nothing else takes it) is `Action::UseBlock`, checked against `USE_REACH`. `Scripts::tick` hands creations at most `BLOCK_EVENTS_A_TICK`. A player's own use of a creature or of a block a creation listens for lifts the 10 s quiet after they closed its question.
- **Healing and meters** (world 0.6 and 0.7, ui 0.2): `world.healing` rates live in `GameShared.healing` per (player, creation), multiplied in `Scripts::healing_changes`, and reach the host's own `Me.healing` or others as `Msg::Healing`; `player::walk` scales natural healing by it. A hurt with `down_to` (world 0.7) goes as `Msg::HurtTo` (or into `Me.hurts`), since only the player's own game knows how much it can take. `ui.meter` is a `Piece` at `METER` with a fill and colour; `update_hud` lays up to `MAX_METERS` beside the health bar (the health bar's share hides outside survival).
- **Things to hold and tools** (world 0.8): items (`items::ITEMS`, from 256: pickaxes, axes, shovels, swords, hoes) are carried and held but never placed (`player.rs` won't, `world.set_block` errors); their icon is an atlas tile named in `Item.icon`, painted in `textures/art/tools.rs` (what ores give in `textures/art/ores.rs`, with the ores, old chests and glowcaps). Block ids 64 to 71, where tools were before, are the ores, the old chest and glowcaps (72 is the balloon basket, an ordinary model block). Each game reports what's in hand as `Action::Held` (`GameShared.held`, `world.held`). `world.digging` (speeds by `sound::Material` kind and a level) lives in `GameShared.digging` per (thing, creation); `Scripts::digging` multiplies the speeds and takes the highest level, and every game gets them as `Msg::Digging` (on change and in the welcome). `world.drops` (world 0.13: what breaking a block gives, and the level it needs) lives in `GameShared.drops` per (block, creation), the last said counting, and goes out as `Msg::Drops`. Both land in `Me.rules` (`items::Rules`): `Me::dig_speed` is 0 for a block the hand can't reach, `player::build` tells the player which tool would (`player::needs`) and gives `Rules::gives` when a block breaks. The test harness's `test.dig` follows the same rules. The base game's ores (blocks 64 to 69), what they give (items 264 to 269) and old chests (70) are the Mining creation's to describe; the Tools creation gives wooden tools level 1, stone 2, copper 3, iron 4 and moonsilver 5 (items 279 to 293 are the copper, iron and moonsilver pickaxes, axes, shovels, swords and hoes, world 0.16), and its anvil (a block it makes) makes the iron and moonsilver ones and mends any tool, while the workbench makes the rest. Wear is the Tools creation's own count, and a hoe in hand digs a square of farmland for Farming. Items 294 to 302 (world 0.17) are shears, a bucket and a water bucket, a fishing rod, a watering can, a sickle, a hammer, and raw and cooked fish, drawn in `tools.rs` too (`Gear`). Interact with an item in hand on water (`player::water_ahead`, kept in `Me.water`, nearer than any block) is `Action::UseBlock` on the water, so creations hear `block_used` with "Water": Buckets and fishing (`creations/water`) fills and pours buckets and fishes, Farming fills watering cans. Items 303 to 319 (world 0.18) are the wool, copper, iron and moonsilver caps or helmets, coats, leggings and boots, and a shield, drawn in `textures/art/armor.rs`. Interact with nothing in reach (no creature, block or water) is `Action::UseItem` with the way the player looks, heard as `item_used` with what's in hand (`Scripts::use_item`); the Armor creation (`creations/armor`) puts pieces on that way and keeps what each player wears in its store. `world.guard` (`GameShared.guard` per (player, creation), multiplied) takes its share off each `world.hurt` as it's called, unless the hurt says `guarded = false` (Hunger's and Fire's do); falls are the player's own game's and aren't guarded. Items 320 to 323 (world 0.19) are a bow, arrows, a sling and a spear, drawn in `textures/art/ranged.rs`. `world.shoot` puts a `script::Shot` in `Outbox.shots`; from the next tick `Scripts::fly_shots` flies it (`shots::advance`: a quarter of a block at a time, the first creature by its bounds or solid block) and `shot_landed` gives the creature `hit(player, shot)` (`event_with`) and calls the creation's landing function (kept in its `Waiting.landed`). `Scripts.shot_news` goes to every game as `Msg::Shot` and `Msg::ShotGone`; each keeps copies in `shots::Shots` and `shots::draw` flies and draws them (sticking in a block it reaches first). `world.aims` (`GameShared.aims`) makes `host_step` turn `Action::Use` and `Action::UseBlock` with that thing in hand into `use_item` aimed at the creature or block. Items 324 to 337 (world 0.20) are seeds, berries, an apple, a baked potato, pumpkin and berry pies, bean and fish stews, porridge, honey, honey cake, a feather, a milk bucket and a fried egg, drawn in `textures/art/food.rs` (the milk bucket in `tools.rs`). - **Creatures walking** (`creatures::step`): walking into something one block high, a creature steps up onto it (`step_up`: lifted, moved on, settled; never onto a fence, which keeps creatures in), and anything taller stops it, so nothing hops by itself (only `creature:hop` and `hop_when_hit` hop). The view shows a step up as a quick climb (`shown_at`). With no `size`, the box it collides with is as wide as its legs stand (or its body across its narrower side), not as long as it reaches, since the box doesn't turn and a long one held pups up on the block beside them; picking a creature uses the box round its parts, turned the way it faces (`Body::bounds`, `ray`), and framing uses `Body::reach`.
- **Fliers and changing kind** (world 0.9): `KindDef.flies` makes `creatures::step` skip gravity and ease `vel.y` toward `Body.climb` (`FLIER_EASE`), slowing near `WY + FLY_ABOVE`; in the air a flier's speed follows its rider gently (`FLIER_GRIP`), and on the ground it ignores them. `creature:become` restyles the body to another `KindDef`, bumps `rev` (so clients get the new `Look`) and swaps the instance's metatable to the new kind's table. On a friend's game `creatures::ride` eases the rider after their mount, which it hears of only 20 times a second. The Hot air balloon is four kinds (empty, filling, full, burner on) of one creation, and keeps balloons' places in its store, since the herd isn't saved.
- **Behaviours** (world 0.10, `behaviours.rs`): `KindDef.behaviours`, parsed by `behaviours::parse` with plain errors. `behaviours::step` runs in `Scripts::tick` for each creation with any, before its Lua handlers (setting `goal`, `wander`, `face`, `says`, and pushing sounds to `GameShared.sounds`), and `behaviours::react` in `Scripts::event` before `used` and `hit`, so the creation's code has the last word. What each creature is doing (who it follows, fleeing, the next chatter) is `Scripts.behaving`, outside the VM, so hot reload keeps it. Food is what `GameShared.held` says a player holds. The woolly and the duck use them, and the woolly's tests check following food, following when used and running off.
- **Blocks made by creations** (world 0.12, `made.rs`): `[blocks.name]` in a creation's potluck.toml is read by `made::read` (pictures as rows of letters with `colors`, a shape, boxes in sixteenths, `kind`, `hardness`, `light` and `glow`). `Scripts::start` registers them on the host before the code runs, so they work by name at once: each gets an id from `blocks::FIRST_MADE` (128) up that the world keeps (the same creation and key keep their id; a new picture redraws it). `blocks::block()` finds them through an array of leaked `Block`s (`MADE`, one atomic load, as meshing looks up every block), and `by_name` after the game's own; an id with no block is the magenta "Unknown block". The list (`made::Entry`: id, creation, key and the table as written) goes in the welcome and whenever it changes (`Msg::Made`, PROTOCOL 17; guests `adopt` the host's ids exactly) and in the server's save (`POTLUCKW2`, `made::world_bytes`/`read_world`; `restore` gives a saved block a new id when its own is taken and `Voxels::renumber` follows; `POTLUCKW1` still loads), so a world shows its blocks even when the creation's gone. In the game `made::MadePlugin` draws new pictures with `BlockAtlas::put` (plain tiles after the game's, glowing ones from the far end, as `build` lays them out) and sends each tile's mip levels to the graphics card itself (`TileWrite`s through the render world's `queue.write_texture`), since the atlas images live only there; then it redraws the chunks with made blocks, finds their lights and gives the map their colours. A moving block (world 0.14: `frames`, `speed`) has a face that changes from frame to frame drawn with `BlockAtlas::put_moving`, which works out every frame's colour and glow writes once; `made::Moving` keeps them (32 MB at most, past which pictures stay still) and `animate` sends a tile's writes only when its frame changes, always the first with the Reduce flashing setting on (`made::frame_at`). The atlas has room for about 150 more tiles. A block with `turns` (world 0.15) is four blocks (`key`, `key>1` to `key>3`, the turned copies registered after the creation's own and left out of what `register` returns): each turned copy has its own top tile (`turn_picture`, clockwise) and boxes turned with it, and shares the side and bottom tiles; `blocks::base`, `facing` and `turned` go between them, drops, finding, the creative pick and the Blocks sheet go by the base, and `player::build` turns what it puts down to face away from the player (`quarter_looking`). A box with `joins` is a `Cuboid` shown only beside a block of the same creation (`When::Kin`, from `Block.kin`). Circuits (`creations/circuits`) is the example: wire, sources, inverters, delays, lamps and gates in one creation that works its own power out ten times a second. Tests share one process, so made blocks registered by one test are seen by others: give test blocks names of their own. The market checks blocks (`block_problems`, keep in step with `made::read`), reads their names for words and draws each one's side on the creation's page. Brickworks is the example: six blocks in letters, and a kiln.
- **Blockbench models** (world 0.11, `model.rs`): `world.model(file, scale)` reads a `.bbmodel` (Blockbench's own JSON project file, kept as text like any creation file) into the same Luau list of boxes a hand-written `body` is, and `body = "file.bbmodel"` is short for it, so parsing a body stays in `parse_kind`. Cubes become parts (16 px to a block, centre and size, `inflate` grows them), coloured by the most common colour on their faces in the texture (decoded from the file's `data:image/png` source), else Blockbench's marker colour, and carry `Part.paint` (`Painted`: the file, texture, each face's rectangle 0 to 1, a tint from how far code moved the colour, and a stamp of the file). Only that goes between games (PROTOCOL 16): `creatures::draw` decodes the picture from its own `Library` copy (`model::image`) and draws `painted_mesh` with a nearest-filtered, alpha-masked material, falling back to colour and skin when it can't; `head`/`leg`/`glow` come from the cube's and its groups' names (old outliners carry names, newer files keep them in `groups`). Rotations and meshes can't be upright boxes, so they're drawn upright or left out and the log says so. The market reads models with `model_cubes` and checks only their names for words (keep it in step with `model::read`); a creation's page lists its buttons, own sounds, models, client half and tests (`web::contents`), and shows a model as its picture and cubes (`model_view`), never its JSON. The Hedgehog is the example: a model, behaviours and no code.
- **The Old Greens** (`creations/old-greens`): a creation that finds a place for each of three ruined greens when a world starts (a few hundred columns a tick, far from the Green, on natural ground), builds them a tick each, and keeps where in its store (with `built`, so a reload carries on). A hearth (Clay pot) lit with a lantern and what's round about becomes a Brazier. Store goes with the world: leaving for a fresh one (`Act::Leave`) clears it, or rebuilt worlds would skip the ruins and respawn the last world's balloons.
- **Client halves** (`halves.rs`, `@potluck/net`): a creation's `client` file runs on every game with a player at the screen (the host's own too, never the server), in its own sandbox with 16 MB and 4 ms a frame. It has net, `ui.show`/`hide` and `sound.play` for its own player, world's timers, its own clock and dice, and the time of day (`Halves.day`), and from net 0.2 it reads this game's copy of the world: `halves::run` builds a `Seen` each frame (the voxels, the players this game knows of, where the player looks and aims) and `Running::seeing` binds `world.block`, `top`, `find_block`, `players` and `nearest_player` to it with `lua.scope` for the frame, putting stubs back after (`READS`). Everything else (`HOST_ONLY`) errors with where to do it. `@potluck/test` 0.3's `test.sent` and `test.from_half` let a creation's tests check its messages to and from halves (the harness drains `GameShared.notes`); the half itself is tested in Rust (the balloon's altimeter). The host's half talks to its creation through `Me.notes` and `Actions` like any player's (`Msg::Net` down, `Action::Net` up), and `Scripts::hear` rate-limits each player. Halves start afresh when the creation's files change or `Library.world` moves on (a new world). Base creations embed extra files with `base!["id" + "client.luau"]`.
- **Kept worlds** (`worlds.rs`): Play alone and Host open Screen::Worlds; `worlds::acts` (before `game::do_acts`) makes, plays, renames and deletes them and saves before Leave and Quit, and `autosave` saves every two minutes and when the pause menu opens. A save is `made::world_bytes`, store.json, boards.json, creations.json (the player's own by folder, others' whole) and player.json (`Stood`: blocks by name, so ids can move), in `worlds/<id>/` beside meta.json. Every seed is the same island (`world::height_at`'s landmarks are fixed), so a new world takes a random one. The title's island (`crate::SEED`) is never saved: `--play`, `--shot` and the demo use it, and Leave goes back to it. Guests' pockets aren't kept by the host yet.
- **Type checking** (`check.rs`): `luau-analysis` is a Rust port of Luau's own checker (pure Rust, so no clash with mlua's C++ Luau), pinned with its sibling crates at one exact version. `check()` runs it in strict mode over a creation's top-level `.luau` files, resolving `@potluck/<module>@<version>` to the matching type in `creations/types/potluck.d.luau` (a client half's net to `ClientNet`) and its own files by name, with a time limit per file and a panic guard. The new solver is noisy on unannotated code (it infers `self` and positions as unions), so `hint()` keeps only four kinds it's sure of: a key a known table hasn't got (the API's types and Luau's own libraries, with the closest name), an unknown global, a call's count of values, and a literal of the wrong kind; everything else is dropped. Every base creation must come out with no hints (a test checks), so a new false alarm shows up there. `keep_checking` rechecks the player's own creations (never others') on a thread when their files change, two at a time, and Look inside shows the first five; the bridge's `check` tool and `--typecheck` call `check()` directly. The market doesn't run it yet.
- **Sounds** (`sound.rs`, `@potluck/sound`): every sound is made from numbers at start (`synth`, the same each time; no files), and `sim()` adds the playing systems only when Bevy's `AudioPlugin` is there (the game, not the server). Anything that makes a sound pushes a `sound::Play` onto `Heard`; creations' go through `Scripts::sound_changes` to the players near enough (`Msg::Sound`). Block sounds come from `sound::material`, by the block's name, so new blocks need no list here. A creation's own sounds (sound 0.2) are `[sounds.name]` tables in its potluck.toml (`Manifest.sounds`, kept as JSON values), read by `sound::recipe` with plain errors (a bad one stops the creation loading) and checked by the market's `sound_problems` (keep the two in step). `sound::Own` resolves what a creation plays, its own first, to "creation/name" with its caption; every game already has the creation's files, so `Sounds::get` makes each one from its recipe (`make_own`, seeded by that name) the first time it plays and again when the recipe changes, and no message carries sounds. `POTLUCK_SOUNDS=DIR cargo test --workspace -- --ignored write_the_sounds` writes them all as WAVs to listen to.
- **The map** (`map.rs`): `MapImage` keeps a colour and height for every block column ever drawn, a tile per world column (`surface`, `shade`: the block's colour from its icon, slopes lit, water bluer the deeper), drawn as columns come in (`Voxels::since`, 32 a quarter second, nearest first) and after that only the spots in `Voxels::map_dirty`, a few times a second; land nobody's seen is `UNSEEN`. Its picture is a `SIZE` (768) block window that follows the player, or the full map's middle while it's open (`follow`). Under a roof (`roof_level`) it shows the level the player is on, within `LEVEL_REACH`. The minimap is drawn on the CPU into a 196 px image (`draw_minimap`, so tests check its pixels); the full map is the window's picture shown through `ImageNode::rect`, with markers over it and its list as an ordinary menu (`map::fill` makes the items into `Focus::made`; `map::map_acts` takes its acts before `game::do_acts`). Nothing moves the camera: the map opens at once.
- **Waypoints and trips** (`waypoints.rs`): kept on each device in `waypoints.json`, per world (`world_key`: the seed for a world made here, the address and seed for one joined). Outside survival a player goes anywhere at once; in survival only to their own waypoints at places they've stood (`stand`), after `WAIT` seconds standing still and `REST` seconds since the last (`may_go`); a server's `teleport = false` stops both. A trip fades the screen to dark, puts the player at `landing` (clear of blocks, on the ground or the canopy) and fades back. Positions are the client's own, so a trip needs no message.
- **Chat** (`chat.rs`): every line goes through the host (`Msg::Say` up, `Msg::Chat` down), even alone, so LAN worlds chat with no internet. The host tidies it, hides `assets/chat_words.txt`'s words (a server's own `chat_words.txt` in its data folder instead), limits each player to `RATE`, holds younger players (`Hello.young`) to `QUICK` lines and sends joiners the last `HISTORY` lines; a server logs every line to `chat.jsonl`. For a bridge to Fluxer later: `Line::from` says where a line came from, `Chat::outbox` holds the lines that may leave (players' own, never a younger player's), `Chat::inbox` takes lines from outside, and younger players' games never get a bridge's lines. A parent's `Settings::chat` off hides and sends nothing. A pad types on the keyboard on the screen (`keyboard.rs`; A on any field opens it, and Done does the button after the field as Enter does).
- **Jams** (`jams.rs` in the market, `green.rs` in the game): a moderator sets a theme and dates on the web; makers enter creations shared to Everyone (three each); stars given while it runs rank the entries, and the top four of a jam that ended in the last 30 days come first in `/api/green`, then this week's entries, then trending. The game asks for it (anonymously, with the young header) on entering a world and every half hour, and its arches show the world's own non-base creations before those picks. The arch geometry is `world::portal_xs()` and `PORTAL_Z`.
- **The dev bridge** (`bridge.rs`): with `Settings::dev_bridge` on (or `--bridge[=PORT]`; `POTLUCK_BRIDGE_PORT`), the game listens on `127.0.0.1:47130` for MCP's Streamable HTTP, answering each JSON-RPC message with plain JSON (no stream), and refuses any request whose Host or Origin isn't this computer, so web pages can't reach it. Its threads only pass calls to `bridge::serve`, which answers them on the game's next frame with the same calls the menus use (`game::bring_checked`, `Scripts::run`, `KnobEdits`); a screenshot answers from an observer when the frame's captured. `sim()` adds it only where there's a window. Tools are `bridge::TOOLS`; keep them, AGENTS.md's list and the test in step. `test` runs on a thread of its own with a copy of the world, so the game doesn't stop while it plays.
- **Creations' own tests** (`testing.rs`, `@potluck/test` 0.2): `testing::TEST_MODULE` is Luau, made in every sandbox; `test.case` keeps cases in a table it shares with the harness (`Vm.test_harness`). `testing::run` gives each case a fresh `Scripts`, `Herd` and copy of the world, with only that creation, plays a tick, then resumes the case as a coroutine inside `Vm::session`. Actions (`wait`, `player`, `place`, `press`...) yield to Rust, which does what the game would (`Scripts::player_block`, `event`, `press`, `answer`, `creatures::step` and `tick`) and resumes; looks (`kind`, `creature`, `health`, `shown`, `asked`, `heard`) read what `Harness::tell` wrote (`Harness::listen` counts the creation's sounds) before each resume, so they never yield in the middle of a scoped world call, whose functions die when the session ends. Base creations' tests are embedded with `base!["id" + "test.luau"]` (in the market's `BASE` too), and `base_creations_pass_their_own_tests` runs them all.
- **Lighting tiers** (`render::Tier`): Low for integrated graphics and the Steam Deck, Medium the default, High and Ultra for desktop cards. Low has no atmosphere or bloom, so its sky is a dome of vertex colours round the camera (`render::dome`, meeting the fog at the horizon) and its flames glow dimmer so they keep their colour. With the `raytracing` feature, Ultra on a card with ray queries lights the world with Solari instead of shadow maps and fog (`render::Raytraced`): meshes then carry only position, normal, UV and tangent (no vertex colours), water, plants and glass (their own chunk layer) stay out of the ray traced scene, and everything ray traced counts as opaque, so the tracer sees leaves as a porous stand-in (`mesh::porous_leaves`: each leaf block a smaller box nudged about its cell) and light comes down through the canopy in patches. By day the eye opens up under trees and roofs on every tier, by how much sky the player sees (`mesh::sky_seen`), most when ray traced. Judge looks on a real GPU (lavapipe is slow and renders differently), and bake final block textures on one too (`CYCLES_DEVICE=OPTIX`); quick cloud bakes are previews, not for committing.
- **Block models** (`Shape::Model`): boxes in sixteenths of a block, like Minecraft's. Each face shows the part of its tile it covers, so a model's side tile is painted as a picture of the model from the side (which is its icon too). Boxes can show only beside a twin or a full block (`When`), which is how columns stack and fences join; a box marked `glow` goes in the glowing layer, and blocks with `light` get real lights near the player (`render::lamp`). Block ids 29 to 63 are for the looks, 64 and up for the creations' work.
- **The far land** (`render/far.rs`): every column in reach that isn't drawn (`far::reach`: 360 blocks on Low, where the fog has hidden the rest, 830 above) is drawn from the seed instead, a grid point every 8 blocks (`far::Spot`: `wild::height`, the biome, the climate and `wild::tree_cover`, which keeps in step with `tree_at`), coloured from the map's palette (grass tinted as the drawn grass is, woods as a darker, lumpy canopy), with skirts down its sides next to drawn columns and the water over it tinted by depth as drawn water is (`mesh::water_tint`, `UNDERWATER`). Toward the far end the land sinks into deep sea, and past it the open sea goes on to `OPEN_SEA` (12 km; the camera's projection has no far end and the sheets aren't culled) to meet the sky. A column counts as drawn once all its chunks have been meshed, and stays so while it's shown, so a changed block never opens a hole. It's made again on `AsyncComputeTaskPool` whenever the player moves a grid step or the drawn columns change, one job at a time, keeping the grid's points.
- **Climate tints** (`mesh::climate_tint`): grass and leaves are yellower where it's warm and dry, cooler where it's cold and deeper where it's wet, worked out at each column's corners and blended between (`mesh::Tints`). The tint is exactly white in the island's climate, so the island and the lands near it keep their colours (a test checks it).
- **Under water** (`render::sky`, `UnderSea`): the fog closes in to `UNDER_SEA` blocks in the water's colour (`under_water_colour`: darker going down and at night, brighter toward the sun), a ball round the camera hides the sky and far land behind the murk, and the grade turns cool. Nothing sways or wobbles.
- **Sky light** (`mesh::Sky`): each chunk vertex carries how much of the sky it sees (rays up from the open cells beside it, stopped by solid blocks and dimmed by leaves, glass and water) in its second UVs, and the chunk materials read the ambient curve (`mesh::sky_ambient`) through them as their occlusion texture. So rooms, caves and forest floors lose the sky's fill light but keep direct sun and lamps. A block change remeshes the chunks it can shade a few at a time (`Voxels::shade`). Ray tracing finds the sky itself and skips it.
- **Detail by distance** (`mesh::Detail`): chunks near the player get every tuft, leaf fin and the wind; further out fewer, wider tufts that keep still, past 112 blocks no leaf fins and past 176 no tufts. Only near ground cover casts shadows. `POTLUCK_OFF=tufts,fins,lips,wind,lod,sky,rtleaves,rtsolid,pack,cube` and `POTLUCK_HIGH_OFF=ssao,contact,haze,taa,shadowmap` leave things out for measuring what each costs (`POTLUCK_HAZE_STEPS=n` thins the haze instead); the haze is drawn only while the sun is up or near it, since in the dead of night it has nothing to light it; hold every tier to 60 fps at 1440p on the p16g3 (Low to 40 on a Steam Deck).
- **Graphics memory** (`memory.rs` reports it on quitting): chunk meshes are packed (`mesh::pack`: 36 bytes a vertex in place of 72, positions kept full so chunk edges meet; ray traced meshes stay full, since Solari reads them), the unused point light shadow cube is 16 pixels, and wgpu takes memory in small blocks (`MemoryHints::MemoryUsage`), which together halve what the game reserves with no visible change. `POTLUCK_OFF=pack,cube` and `POTLUCK_GPU_BLOCKS=big` put each back for measuring.
- **Frames to the screen:** play waits for the screen (FIFO; `smooth_present` in main.rs), except when the game draws on a graphics card with no screen plugged in (`pick_present`: laptops that hand each frame to another chip, like the p16g3 on NVIDIA), where plain vsync dropped it to 35 to 46 fps and mailbox holds 60. Mailbox on the desktop's own card draws as fast as it can, and Mir (Umoja) drops every frame whose fence hasn't signalled when the next arrives, so on amd-halo the window stopped updating; NVIDIA is safe there because main.rs turns its explicit sync off. `--present=` picks a mode for measuring.
- **The window:** play fills the screen (borderless) unless `Settings::fullscreen` is off; F11 and Settings switch it (`full_screen` in main.rs), and `--windowed` or `--size` opens a window once. The tools draw at their own size.
- **Menus** (`ui.rs` says what's on each screen, `ui/draw.rs` how it looks): short menus are words on a shade down the left over the world, the chosen line marked in mint ("open air"); screens to browse or read (Creations, the market, Look inside, servers, suggestions) sit on a near-solid sheet. Sizes are for a 720-line window and scale with its height. Settings and Creations have pages (`ui::pages`: LB and RB, Tab, or a click). Behind menus that cover the world, `render::MenuBlur` (a `FullscreenMaterial`) softens it, except on Low. Creations' cards show pictures `photos.rs` takes of their creatures while the sheet is open. Titles are Bungee (`Ctx::heading`, all capitals, and the little labels over them), menu lines Barlow SemiBold (`Ctx::round`) and small text Barlow Medium (`Ctx::plain`); none of them has arrows or triangles, so marks like More above are drawn. The title screen shows the game's name as a picture (`Fonts::logo`, `assets/title/potluck.png` from `tools/title.py`).
- **Comfort:** no head bob or camera shake; the field of view is a setting. Swimming (`player::swim`) eases every speed to where it's going, and floating rests critically damped, so the view never bobs on the water.
- **Controller first:** everything works on a pad, and the keyboard and mouse always work too.
- **The game server key** is `defaultkey` in git; CI writes the real one to `server.key` (read by `build.rs`), never committed. The version comes from `tools/version.sh` through `POTLUCK_VERSION` or a `VERSION` file.
- Player-facing text is plain and short, in the game's words (creations, Look inside, Tweak, Remix, the Green, Mossbacks).

## Releases

Pushing to `main` builds the `potluck`, `potluck-server` and `potluck-market` snaps for amd64 and arm64 (`snap.yml`, which also installs the market's on the runner and checks every part answers) and the Windows and macOS zips (`desktop.yml`). Publishing snaps waits on the names being registered, the `STORE_LOGIN` secret and the `PUBLISH_SNAP` variable. Versions are `vYYYY.WW.MINOR` tags from `tools/version.sh`, as in the other games. Signing in and the older share codes need `potluck` registered on game-server (share kind `creation`); the market and the relay are deployed as the `potluck-market` snap (docs/hosting.md). Everything is deployed as snaps, never containers.
