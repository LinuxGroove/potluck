# Potluck

A block sandbox where every creature, block and mini game is a Luau creation players can read, tweak, remix and share by code, in Rust on Bevy 0.20 with Luau through mlua. The concept is idea 26 in [game-ideas](https://github.com/LinuxGroove/game-ideas/blob/main/ideas/26-potluck.md). Like Cinderkirk it is **not Godot** and doesn't use the shared add-on; it talks to the shared [game server](https://github.com/LinuxGroove/game-server) over its REST API (signing in, the codes made before the market, the launch ping), and its own market (`crates/share-service`) keeps and lists creations.

## Commands

```sh
cargo build --bins                         # the game (potluck), the server (potluck-server) and the market (potluck-share)
cargo test                                 # world, creations, sandbox, a friend joining, wss and https, the market's checks
deploy/market/test.sh [docker|podman]      # the market end to end against Forgejo in a container: sharing, reviews, a remix of a remix, a suggestion merged from the game
cargo run -p potluck-share -- --config deploy/market/share.toml   # the market (FORGEJO_TOKEN from the environment); potluck-share check FOLDER runs its checks
cargo run --bin potluck -- --play          # straight into the world
cargo run --bin potluck --features raytracing -- --play --lighting=ultra   # Ultra ray traced (Bevy's Solari), on cards with ray queries
cargo run --bin potluck-server -- --port=47126 [--config=server.toml] [--tls-port=47443 --cert=fullchain.pem --key=privkey.pem]
cargo run --bin potluck-bots -- --address=ws://127.0.0.1:47126 --bots=50 --minutes=60 --build --report=/tmp/soak.jsonl   # bot players for soak tests
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1280x720x24" target/debug/potluck --demo=/tmp/demo --size=1280x720   # scripted play-through, recorded (about 1.5 s a frame on 4 CPUs)
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1600x900x24" target/debug/potluck --shot=/tmp/a.png --after=8 [--at=x,y,z,yaw,pitch] [--time=0.8] [--at=creature:N] [--person[=hue]] [--screen=play|inside|tweak|pause|title] [--lighting=low|medium|high|ultra] [--no-vsync | --present=immediate|mailbox|fifo|relaxed] [--latency=N] [--onscreen] [--timings]   # logs the frame rate too; --timings adds where frames go (lengths, main and render world, waiting for the screen) and each render pass's CPU and GPU time
tools/tiers.sh [out=/tmp/potluck-tiers] [size=2560x1440] [binary]   # every lighting tier from four places, with frame rates (on a real graphics card)
tools/server-snap.sh build/potluck-server && (cd build/potluck-server && snapcraft pack)   # the server snap
CYCLES_DEVICE=OPTIX python tools/blocks.py -- assets/blocks 256 [only=grass_top,dirt]   # bake block textures (bpy wheel in a venv; drop CYCLES_DEVICE without a GPU)
```

Run the tests before every commit. Set `POTLUCK_HOME` to a scratch folder for runs that shouldn't touch your own world and settings. Without a GPU, launches take a minute or more under lavapipe (most of it Bevy's pipelines compiling); `libxkbcommon-x11-0` and `mesa-vulkan-drivers` must be installed. A local `.cargo/config.toml` with clang and mold speeds up linking; it isn't committed.

## Layout

| Path | What |
|---|---|
| `crates/potluck/src/lib.rs` | `sim()`: everything a world needs without drawing, shared by the game and the server |
| `src/main.rs`, `src/server.rs`, `src/bots.rs` | The game (window, drawing, input, `--play`, `--shot`, `--demo`), `potluck-server` (MinimalPlugins at 30 Hz, server.toml, pinned creations, the market's server list, autosave, saving on stop) and `potluck-bots` (bot players for soak tests) |
| `src/hosting.rs`, `packaging/server.toml` | A server's settings (`ServerConfig`; the example is every setting, commented), who may join (`Rules`, passes from the market), boards, tick times |
| `src/world.rs`, `blocks.rs`, `noise.rs` | The 384 x 128 x 384 island from a seed, the Green, blocks (block models are `Cuboid`s), the save format (`encode`/`decode`) |
| `src/world/places.rs` | The camp, the terraced farm and the sandstone villa the gallery's views look at |
| `src/mesh.rs`, `textures.rs`, `render.rs` | 32³ chunk meshing in three layers, the generated block atlas (glowing tiles kept apart), sky, sun, lanterns, the lighting tiers (`Tier`: Low, Medium, High, Ultra) |
| `src/player.rs`, `input.rs` | Walking, flying, building, survival; controls read once a frame into `Controls` |
| `src/script.rs` | Luau VMs (one per creation, sandboxed, memory and time limits), the API, knobs, events, hot reload keeping creatures' state |
| `src/halves.rs` | Client halves: a creation's `client` file, run on each player's own game with `@potluck/net` and a small part of the API |
| `src/creatures.rs` | Bodies made of boxes, walking, riding, drawing; parts wear painted skins chosen by name (`textures/skins.rs`), and players' bodies are `Person`s (placed by `net`, dressed and walked here) |
| `src/creations.rs` | Creations on disk and embedded (`BASE`), the library, Remix, watching folders |
| `src/net.rs`, `transport.rs` | Host-authoritative worlds: messages (`Msg`, bump `PROTOCOL` when they change), what each player hears about (players and creatures within `NEAR`, as changes), WebSocket over TCP or TLS, the status page, the LAN beacon |
| `src/share.rs` | The market's client (sharing, loading signed creations, suggestions, merging, sign-in links for the QR code), signing in to the game server and its older codes, the launch ping |
| `src/ui.rs`, `game.rs` | Menus (`Screen`, `Act`), HUD, what menu choices do, interacting |
| `src/green.rs` | The Green's four arches: what players brought, then the market's picks (`/api/green`), aiming at them |
| `src/demo.rs` | The scripted, recorded play-through |
| `src/tests.rs` | Tests that need no window |
| `src/textures/art.rs`, `art/props.rs` | The blocks' 64 px pixel art, painted from code (palettes, cells, heights for the normal map, roughness per texel); it wins over the bakes. `props.rs` paints the block models' tiles. `POTLUCK_DUMP_TEX=<dir> cargo test dump_textures` writes every drawn texture out |
| `tools/blocks.py`, `assets/blocks/` | Block textures baked in Blender (colour, normal, roughness, see-through); `build.rs` builds in whatever is in `assets/blocks`, and drawn textures fill the gaps |
| `creations/` | The base game's creations (each folder listed in `BASE` in `creations.rs` is embedded at build time), `AGENTS.md` (the API, copied into every remix) and the API's types |
| `crates/share-service/` | `potluck-share`, the market: `market.rs` (sharing, versions, remixes, suggestions, moderation, sign-in links), `servers.rs` (passes, the server list, boards), `jams.rs` (jams, entries, favourites, the Green's picks), `forgejo.rs` (repositories, commits, tags, pull requests; remixes copy history with git, since Forgejo allows one fork per person), `devices.rs` (one account on several devices: link codes, recovery codes), `checks.rs`, `store.rs` (files by hash, folder or S3), `db.rs` (the SQLite index), `api.rs` (the game's API) and `web.rs` (the pages, in maud), `avatar.rs` (block heads), `tests.rs` |
| `deploy/market/` | The market's config, word list, Dockerfile, compose file (Forgejo, the service, Caddy) and `test.sh` |
| `snap/`, `packaging/potluck-server/snap/` | The game's snap and the server's (with Caddy for `domain`); `tools/server-snap.sh` makes the server's project folder |
| `docs/api.md` | The creation API's modules, limits and the promise that goes with them |

## How the game is built

- **One world, many views.** `sim()` holds the voxels, the library, the running creations and the herd. Alone or hosting, `game::host_step` runs creations and creatures; a client only mirrors what the host sends. The server is `sim()` with no window and no `Me`.
- **Creations are the game.** Base content is creations too (`creations/mossback`). A creation's VM never touches Bevy: calls go through a scoped API that reads and changes the world and herd, and anything a creation can do must be safe for a stranger's code: no files, no network, no `loadstring`, a memory cap and an interrupt deadline. `AGENTS.md` and `types/potluck.d.luau` describe the API; keep them in step with `script.rs`, and version API modules on their own (`@potluck/world@0.2`, `MODULES` in `script.rs` and in the market's `checks.rs`). docs/api.md is the promise: a minor version only adds, every major stays, the limits only loosen; update its tables and change list with every module change.
- **Hot reload keeps state.** Restarting a VM carries each creature's fields over as JSON and restyles bodies; tests check it.
- **Networking** is WebSocket binary messages: tag 0 is a JSON `Msg`, tag 1 the world's bytes. The same port answers plain HTTP with the status page and `/status.json`. TLS comes from a certificate (`--cert`, `--key`) or a proxy in front (the snap's Caddy). Each player hears only about players and creatures within `NEAR` (144 blocks), as changes since what they last heard, with far ones (past 32) a quarter as often; names and kinds go once. Keep messages small: soak with `potluck-bots` after changing what's sent.
- **Servers** (`hosting.rs`, `server.rs`): `Rules::admit` decides who comes in. A pass is the market's Ed25519 signature over `{handle, name, aud, exp}`, checked with the key the server fetches at start; `aud` is the address the player typed, compared by `same_address`. Creations keep boards through `@potluck/game` (`Scripts::shared`), saved in `boards.json` and pushed to the market with the heartbeat; `game.send` uses the server's `[links]`. What creations keep with `@potluck/store` (`script::Store`, 64 KB each) is saved beside them in `store.json`.
- **The market** (`share.rs` in the game, `crates/share-service`): the game signs in to the game server with its device id and gives the market that session, which the market checks with the game server; no emails or passwords. An account is keyed by the first device's id; other devices join it with a link code or a one-time recovery code (`devices.rs`: `devices` maps a device to the account it plays as, so `game_account` resolves through it, and codes are kept as hashes). The market keeps one code per creation that loads its newest version anyone may load, signs each version's manifest (Ed25519; release builds carry the key as `POTLUCK_MARKET_KEY`, others keep the first one seen) and serves files by SHA-256, which the game checks and caches. Codes made before the market still load from the game server, and sharing by code falls back to it when the market is down. A remix's `potluck.toml` carries `[from]` (code and version, or a base creation's id), and `market.json` in the data folder keeps each of the player's creations' code and version there.
- **Ages** (`Settings::young`, the market's `accounts.young` from the game's `X-Potluck-Young` header, `versions.all_ages`, a server's `all_ages`): asked once before anything goes online (`game::goes_online`); younger players share by code only, send no suggestions, have no about line, and listed servers that aren't all-ages refuse their passes. Parent settings sit behind a hashed PIN. New market columns go in `db::ADDED`, so older databases gain them on start.
- **Creations' buttons** (`@potluck/input`): actions are `[actions.id]` in `potluck.toml` (name, pad, keys), so the game and the market know them before anything runs. `input::claim` makes the live creation's buttons (riding its creature, or `input.focus`) do its actions instead of the game's; `game::interact` sends `Action::Press` to the host on each change, and the host takes a press only while it's live for that player. `input.focus` reaches players as `Msg::Focus`. Players' own buttons are `Settings::bindings`. Keep `PAD_BUTTONS` and the keys in `input.rs` and the market's `checks.rs` in step.
- **Creations' screens** (`@potluck/ui`): `ui.show` and `ui.ask` change `UiState` on the host; `Scripts::ui_changes` turns that into what each player should see, sent as `Msg::Piece` and `Msg::Panel` (or straight into `Me` for the host's own player). A panel opens as `Screen::Panel` only from play, never over a menu, always says whose it is and always has Close; `Action::Answer` goes back to the host, which checks it against that player's panel. Every question gets one answer, nil included, on a later tick.
- **Client halves** (`halves.rs`, `@potluck/net`): a creation's `client` file runs on every game with a player at the screen (the host's own too, never the server), in its own sandbox with 16 MB and 4 ms a frame. It reads nothing of the world: it has net, `ui.show`/`hide` and `sound.play` for its own player, and world's timers, its own clock and dice; everything else errors with where to do it. The host's half talks to its creation through `Me.notes` and `Actions` like any player's (`Msg::Net` down, `Action::Net` up), and `Scripts::hear` rate-limits each player. Halves start afresh when the creation's files change or `Library.world` moves on (a new world). Base creations embed extra files with `base!["id" + "client.luau"]`.
- **Sounds** (`sound.rs`, `@potluck/sound`): every sound is made from numbers at start (`synth`, the same each time; no files), and `sim()` adds the playing systems only when Bevy's `AudioPlugin` is there (the game, not the server). Anything that makes a sound pushes a `sound::Play` onto `Heard`; creations' go through `Scripts::sound_changes` to the players near enough (`Msg::Sound`). Block sounds come from `sound::material`, by the block's name, so new blocks need no list here. `POTLUCK_SOUNDS=DIR cargo test --workspace -- --ignored write_the_sounds` writes them all as WAVs to listen to.
- **Jams** (`jams.rs` in the market, `green.rs` in the game): a moderator sets a theme and dates on the web; makers enter creations shared to Everyone (three each); stars given while it runs rank the entries, and the top four of a jam that ended in the last 30 days come first in `/api/green`, then this week's entries, then trending. The game asks for it (anonymously, with the young header) on entering a world and every half hour, and its arches show the world's own non-base creations before those picks. The arch geometry is `world::portal_xs()` and `PORTAL_Z`.
- **Lighting tiers** (`render::Tier`): Low for integrated graphics and the Steam Deck, Medium the default, High and Ultra for desktop cards. With the `raytracing` feature, Ultra on a card with ray queries lights the world with Solari instead of shadow maps and fog (`render::Raytraced`): meshes then carry only position, normal, UV and tangent (no vertex colours), water, plants and glass (their own chunk layer) stay out of the ray traced scene, and everything ray traced counts as opaque, so the tracer sees leaves as a porous stand-in (`mesh::porous_leaves`: each leaf block a smaller box nudged about its cell) and light comes down through the canopy in patches. By day the eye opens up under trees and roofs on every tier, by how much sky the player sees (`mesh::sky_seen`), most when ray traced. Judge looks on a real GPU (lavapipe is slow and renders differently), and bake final block textures on one too (`CYCLES_DEVICE=OPTIX`); quick cloud bakes are previews, not for committing.
- **Block models** (`Shape::Model`): boxes in sixteenths of a block, like Minecraft's. Each face shows the part of its tile it covers, so a model's side tile is painted as a picture of the model from the side (which is its icon too). Boxes can show only beside a twin or a full block (`When`), which is how columns stack and fences join; a box marked `glow` goes in the glowing layer, and blocks with `light` get real lights near the player (`render::lamp`). Block ids 29 to 63 are for the looks, 64 and up for the creations' work.
- **Sky light** (`mesh::Sky`): each chunk vertex carries how much of the sky it sees (rays up from the open cells beside it, stopped by solid blocks and dimmed by leaves, glass and water) in its second UVs, and the chunk materials read the ambient curve (`mesh::sky_ambient`) through them as their occlusion texture. So rooms, caves and forest floors lose the sky's fill light but keep direct sun and lamps. A block change remeshes the chunks it can shade a few at a time (`Voxels::shade`). Ray tracing finds the sky itself and skips it.
- **Detail by distance** (`mesh::Detail`): chunks near the player get every tuft, leaf fin and the wind; further out fewer, wider tufts that keep still, past 112 blocks no leaf fins and past 176 no tufts. Only near ground cover casts shadows. `POTLUCK_OFF=tufts,fins,lips,wind,lod,sky,rtleaves,rtsolid` and `POTLUCK_HIGH_OFF=ssao,contact,haze,taa,shadowmap` leave things out for measuring what each costs; hold every tier to 60 fps at 1440p on the p16g3 (Low to 40 on a Steam Deck).
- **Comfort:** no head bob or camera shake; the field of view is a setting.
- **Controller first:** everything works on a pad, and the keyboard and mouse always work too.
- **The game server key** is `defaultkey` in git; CI writes the real one to `server.key` (read by `build.rs`), never committed. The version comes from `tools/version.sh` through `POTLUCK_VERSION` or a `VERSION` file.
- Player-facing text is plain and short, in the game's words (creations, Look inside, Tweak, Remix, the Green, Mossbacks).

## Releases

Pushing to `main` builds the `potluck` and `potluck-server` snaps for amd64 and arm64 (`snap.yml`) and the Windows and macOS zips (`desktop.yml`). Publishing snaps waits on both names being registered, the `STORE_LOGIN` secret and the `PUBLISH_SNAP` variable. Versions are `vYYYY.WW.MINOR` tags from `tools/version.sh`, as in the other games. Signing in and the older share codes need `potluck` registered on game-server (share kind `creation`); the market is deployed on its own from `deploy/market`.
